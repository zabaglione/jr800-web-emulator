# Web UIの構成と開発

Web UIは、C++で実装したエミュレーターコアをブラウザーから操作するための薄いホストです。
CPU、メモリー、デバイス、デバッガーの判定はC++側に置き、JavaScriptはファイル選択、画面表示、入力、音声再生、Workerとの通信だけを担当します。

## ビルドと起動

Emscripten SDKを有効にしたシェルで、静的ファイル一式をビルドします。

```sh
emcmake cmake --preset wasm-release
cmake --build --preset wasm-release
```

生成したページはHTTPサーバーから開きます。
`web/index.html`をFinderなどから直接開く方法には対応していません。

```sh
python3 -m http.server 8000 --directory build/wasm-release/web
```

ブラウザーで`http://127.0.0.1:8000/`を開きます。

ビルド時に、画面・Worker・WASM・翻訳ファイルなどの内容から共通の識別子を生成し、`web/assets/<識別子>/`へまとめます。
どれか一つを更新すると読み込みURLが一式変わるため、古いキャッシュと更新後のWASMが混在しません。再ビルド後はページを通常どおり再読み込みしてください。
配信対象は`build/wasm-release/web/`全体です。`index.html`と`assets/`を一緒に扱い、リンク用の中間生成物がある`web-module/`は配信しません。
開いたままの画面が旧ファイルを必要とする場合に備え、以前の識別子のフォルダーはビルドディレクトリー内に残します。

## 画面の役割

通常画面にはJR-800実機モデルだけを表示します。
SDKアプリは一般利用の実行対象ではなく、折りたたまれた`Developer debugger`内の`SDK application debugging`から読み込みます。

- `JR-800 hardware model`: 実機から用意した`.j8r`、または32 KiBの`.rom`を読み込む。
- `SDK application debugging`: SDKで作成した`.j8a`と、任意の`.j8d`を開発者向けデバッガーへ読み込む。

ROM BASICを試す場合は、所有者が実機から用意した`.j8r`、または32 KiBの`.rom`を選び、`Boot BASIC experiment`を押します。
この操作は、現時点でBASIC起動に必要なRAM、LCD、カレンダー、ポート、キーボードの暫定入力を明示的に適用します。
これらの値は、実機で確定した電源投入時の既定値ではありません。
`.rom`は確認ダイアログ後に同じ起動条件で読み込みます。
「未対応I/Oで停止しない」は初期状態で有効です。未実装のI/O・予約領域への読み取りは`$FF`を返し、書き込みは破棄して実行を続けます。
設定はROM読み込み時に適用されます。無視した回数は開発者向けデバッガーの「無視したI/Oアクセス数」で確認でき、リセット時にゼロに戻ります。
これは実行を続けるための設定であり、接続されていない機器の動作を再現するものではありません。実装済みデバイスのエラーやRAM・ROMの異常は通常どおり停止します。
未対応のアクセスで停止させて調べる場合は、この設定を外してからROMを読み込み直します。
CPU異常による停止は、停止理由とアクセス情報をエラー色で表示します。

「ブラウザーの現在日時でBASICを起動する」は初期状態で有効です。
BASICがRTCの初期化を終えた後に、日時、曜日、24時間制、うるう年カウンターを一度だけ設定します。
対象は2000〜2099年で、ROMは変更しません。
CPUサイクルに合わせて時計が進み、PauseとWebの電源OFF中は停止します。
オフでは元の初期値を使用します。
`DATE$`と`DAY$`の独立した動作は維持し、WAKEによるアラームと復帰は未対応です。

`Load only`は暫定入力を自動設定せず、画面で指定した条件だけを使います。
この操作ではブラウザー日時を設定しません。
`Pause`と`Resume emulation`はCPU実行を停止・再開するだけで、BASICの`RUN`は入力しません。
保存済みBASICプログラムを動かすときは仮想キーボードまたはPCキーボードから`RUN`を入力します。

機械語プログラムは、ROM BASICが安定した後に`.wav`または`.j8a`を選び、`Load and run RAM program`でRAMへ読み込みます。
WAVはWorker内のC++変換器で直接検証し、変換できなければ原因を画面へ返します。
種類は自動判定します。BASICは利用者のROMのLOADで登録し、機械語は指定のRAMへ配置します。
「読み込む」は実行せず停止状態を保ち、「読み込んで実行する」はBASICのRUNまたは機械語の指定アドレスから実行します。
BASICは現在のページを置き換え、読込失敗時は元のセッションを保持します。
[BASICの利用手順](../docs/user/basic-program-wav.md)も参照してください。
この操作は実機のカセット再生時間を再現しません。

## プログラムをファイルへ保存する

エミュレーター内で`SAVE`、`SAVE ...,A`、`MSAVE`を実行すると、完了した内容が「データをファイルへ保存」へ追加されます。
各項目のボタンでJ8A v1とネイティブWAVをダウンロードできます。
ファイル名はROMが保存ヘッダーに書いた名前から作り、大文字・小文字を保持します。
保存一覧は最大32件で、ページを閉じる前にダウンロードしてください。
WAVは48 kHz・16ビットPCM・モノラルです。エミュレーターへの再読込を確認済みです。
BASIC内部形式の1件は、個別にステレオ化したWAVをZOOM H2n・再生ボリューム60で再生し、実機読込に成功しています（実施報告）。ASCII SAVEとMSAVEの実機読込は未確認です。
操作例と一覧の扱いは[保存ガイド](../docs/user/program-save-export.md)を参照してください。

## 言語

初期言語は`navigator.languages`または`navigator.language`を使い、日本語環境では日本語、それ以外では英語を選びます。
画面右上の言語ボタンでいつでも切り替えられます。

英語をHTMLとJavaScriptの基準文字列とし、日本語は`locale-ja.json`に分離しています。
JavaScriptへ日本語の表示文字列を直接埋め込まない方針です。

## POWER OFF／ON

実機を模したPOWER OFFは、ROM・RAM・CPU・デバイスの状態を保持したまま実行を停止します。
POWER ONは、その続きから公称速度で実行を再開します。
BASICの連続実行はスリープのサイクル上限で自動停止せず、次の処理区間へ進みます。
デバッガーで上限を指定して停止した場合は、ONで連続実行へ戻れます。
実機の電源回路やスタンバイ端子を模擬する操作ではありません。RESETピンによるセッション破棄とは別の操作です。

## キーボード

ブラウザーは77個のJR-800物理キー識別子をWorkerへ送ります。
JavaScriptは文字やBASICトークンを注入せず、キー名からキーボード行・bitへの変換はC++側だけが行います。

PCキーボード入力は、ROMを読み込んだ状態で、フォームやボタンなどを操作していないときだけ取得します。
未対応キーはブラウザーへそのまま渡します。
左右のShift、左右のControl、メインEnterとテンキーEnterは、片方を離しただけでJR-800側のキーが解除されないよう入力元の数を管理します。
フォーカス喪失時は、押下中のキーをすべて解除します。
短いキー操作がWorkerの同じ実行区切りで押下・解放されてもROM BASICが見落とさないよう、Web入力は最低49,152 Eサイクル保持します。
これは実時間の待ちではなく、エミュレーター内のサイクルで管理する入力調整です。
通常キーの押下が重なった場合は、先に送ったキーを解放してから新しいキーを渡します。
ShiftとControlは修飾キーとして別に扱います。これはWeb側の文字入力方針であり、実機の同時押しやゴーストの電気的動作を再現するものではありません。

仮想キーボードも同じ構造化キー入力を使います。
ShiftとControlはマウス操作用にラッチでき、フォーカス喪失時には解除されます。
物理的な無入力値が未測定のキーボード行は、C++側へ明示的なRAW基準値を与えない限り不明のままです。

## LCD

LCDは192×64ドットの3状態表示です。
各ドットを不明、消灯、点灯として区別し、不明な値を勝手に点灯または消灯へ変換しません。

画面下の「液晶の見た目」を開くと、濃さ（コントラスト）、背景の明るさ、灰色から緑への色合い、ドットの隙間、消灯ドットの濃さを調整できます。
初期表示は実機写真を参考にした灰緑色の地と暗いドットです。
設定はその場で反映され、このブラウザーに保存されます。「見た目を初期設定に戻す」で表示設定だけを戻せます。
見た目の保存対象は5つの数値です。ROMの保存と削除はROM欄で管理し、RAMは保存しません。
ドットの隙間は表示上の加工です。192×64の論理ドット、CPUやLCDコントローラーの状態は変更しません。
写真の照明や撮影条件は校正されていないため、色と濃淡の初期値は実機の測定値ではありません。

左右のインジケーターは実機写真を参考に、枠の文字と液晶内の三角印を各8段に並べています。
左はPAGE 1〜8、右はCAP.L、GRAPH、カナ、INS、CTRL、RAD、DEG、電池寿命です。
三角印は既知のBASIC表示要求（PAGEはbit 3、モードはbit 2）に連動し、濃さと色合いは液晶の見た目の設定に従います。
不明な表示要求は破線の輪郭で区別し、候補RAM値は各表示の説明で確認できます。
実機での確認では「電池寿命」の消灯は電池切れを示します。エミュレーターでは使用可能な状態として三角印を常時表示します。
この表示は電池残量の計算や候補RAMの値には依存しません。
これはBASICの論理的な表示要求の可視化で、実機の電気的な点灯条件を確定するものではありません。
LCDの構成とアドレスデコードは引き続き暫定です。

## 音声

取扱説明書の`SOUND 音程,長さ`と実機から取得したROM BASICを照合した結果、論理的な音声出力はPort 1 data bit 4の交互変化でした。
CPU内蔵Port 2タイマー出力ではありません。

Workerは音声有効時に64命令ごとに構造化アクセス履歴を読み、このbitの変化を取りこぼさずに取得します。
取得した信号とフレームの開始・終了EサイクルをWorkerの処理ターンごとに送り、無音区間も時間を連続させます。
メインスレッドは公称1.2288 MHzのEクロックを基準に、サンプル化の前に帯域を制限してPCMへ変換します。
約25ミリ秒の再生余裕を持ち、CPUの停止や処理量の上限を待たずに再生します。
音声フレーム間で変換履歴を保持し、20 Hzのフィルターで直流成分を除去します。
これらは折り返し雑音と直流成分を防ぐブラウザー再生用の処理であり、実機の回路特性を表すものではありません。
ROMの内容、実行アドレス、命令列は音声イベントに含めません。

ブラウザーの自動再生制限により、最初のクリックまたはキー操作後に音声が有効になります。
画面右上の`Sound`ボタンでミュートと再開を切り替えられます。
リセットと電源オフでは待機中の音声を破棄します。

この音声はROM BASICの論理出力を再生するもので、実機の出力電圧、アンプ、スピーカー、筐体による音色や音量を再現するものではありません。

## ファイルとプライバシー

選択したROM、WAV、RAMプログラム、デバッグ情報は`File.arrayBuffer()`で読み、ローカルのmodule WorkerとWASMメモリーだけへ渡します。
これらのファイルをサーバーへ送信する処理はありません。読み込みに成功したROMのFileと2つのBASIC起動設定（未対応I/Oの許可、ブラウザー時刻の使用）をIndexedDBに保存します。
再訪時は保存済みROMをファイル選択欄へ戻し、ファイル名と起動設定を表示します。「BASICの起動」を押して初めてファイルの内容をWorkerへ渡します。新たにファイルを選ぶと選択欄も切り替わります。読込失敗時には以前の保存を置き換えません。
「ブラウザー内のROMを削除」は保存コピーだけを消去し、手元のファイルや起動中のセッションを変更しません。保存できない環境では画面に案内し、通常のファイル選択から起動できます。
保存先は同じブラウザー・origin内でページの配下URLごとに分けます。GitHub Pagesの別リポジトリとは選択を共有しませんが、同じoriginの保存領域であるためセキュリティ上の隔離ではありません。ブラウザーのデータ消去、プライベート閲覧の終了、容量管理による削除などで保存内容が失われる場合があります。
プログラム、作業用RAM、デバッグ情報はページを再読み込みまたは閉じると消えます。ページ本体のオフライン保存やクラウド同期は行いません。
GitHub Pagesへの配信設定は[公開手順](../docs/user/github-pages.md)を参照してください。

`.rom`は32 KiBのRAWデータだけを受け付けます。
読み込み前には、実機録音WAVから`.j8r`を作る手順を案内する確認ダイアログを表示します。
拡張子から形式を明示的に選び、`.j8r`の失敗をRAW ROMとして再試行する処理はありません。

## Workerプロトコル

要求は`id`、`command`、コマンド固有の値を持ちます。
応答は`{type: "response", id, ok, result}`、失敗時は`error`を返します。
長時間実行は要求へすぐ応答し、停止時に`stopped`イベントとスナップショットを送ります。

主なコマンドは次のとおりです。

- セッション: `initialize`、`load`、`load-jr800`、`load-jr800-raw`、`load-program`、`load-native-program-wav`、`dispose`、`power-off`
- 実行: `reset`、`run`、`pause`、`step`、`step-over`、`step-out`、`run-to`、`run-to-source`、`run-to-symbol`
- デバッグ: 実行ブレークポイント、メモリー監視点、式監視、シンボル監視、履歴消去、スナップショット
- デバイス: キー状態、RAWキーボード応答、停止中サイクル、カレンダー、音声有効状態

Workerは1000命令単位で音声とキー状態を処理し、最大約8 msの処理区間にまとめてブラウザーへ制御を返します。
BASICの連続実行では、`run`に`realtime: true`を指定し、E-030の公称CPU Eクロック1.2288 MHzに実行済みサイクル数を合わせます。
外部クロック4.9152 MHzをCPU内部で4分周した値であり、命令数を周波数として数えるものではありません。
BASICの表示は2万命令区間の終了時に加え、実行中は約50 msごとにも更新します。
入力待ちでCPUがスリープしていても表示を更新し、連続する区間では時間の基準を引き継ぎます。
100 msを超える遅れは基準を取り直し、バックグラウンドから復帰した際の長い早送りを防ぎます。
JR-800ではデバッガーの通常「実行」も同じ公称速度に制限し、短い押下を過剰な長押しとして扱わないようにします。
単独のWorker呼び出しで速度調整を省略した実行と、合成マシンの実行は速度を制限しません。
JR-800が`SLP`中の場合も、明示した有限サイクルだけデバイス時間を進めます。

デバッガーのブレークポイント、監視点、式評価、シンボル解決、ステップオーバー、ステップアウト、履歴、アクセス記録、逆アセンブルはC++側の責務です。
Web UIは構造化された結果を表示し、命令の意味を再実装しません。

## テスト

WASM Release版のテストを実行します。

```sh
ctest --preset wasm-release --output-on-failure
```

Web UI契約、言語選択、LCD表示、キーボード入力、音声変換、Worker経由の実行を個別に検証します。
配信ファイルのテストでは、WASMだけの更新や間接的に読み込むファイルの更新でも一式のURLが変わり、同じ内容の再ビルドでは変わらないことを確認します。
ブラウザー音声のテストは論理遷移とPCM生成を対象とし、実機スピーカーの物理特性を検証するものではありません。

Chromeでの実行速度と画面更新を検証する追加テストもあります。
PlaywrightとChromeを利用できる環境で、上記のHTTPサーバーを起動して実行してください。

```sh
node tests/browser_run_timing_test.cjs http://localhost:8000/
```

このテストは独自の合成ROMを使い、実機ROMを読み込まずに速度、音声切り替え中の速度維持、一時停止、スリープ、BASIC連続実行の画面更新を検証します。
機能ごとの検証範囲は[対応範囲](../docs/user/compatibility.md)を参照してください。

キャッシュ更新の回帰テストは、一時的なローカルサーバーを自動で起動します。PlaywrightとChromeが必要です。

```sh
node tests/browser_web_bundle_test.cjs build/wasm-release/web
```

独自の小さなWASMでABI 36のキャッシュを作り、同じURLのファイル差し替えだけではエラーが残ることを確認します。
続いてキャッシュを消さずに更新後の画面を再読み込みし、ABI 42の起動と合成ROMによる未対応I/Oの継続を検証します。実機ROMは使用しません。

ROMの永続保存と配下URLでの動作は、PlaywrightとChromeが利用できる環境で次の検査を実行できます。市販ROMは不要です。

```sh
node tests/browser_rom_storage_test.cjs build/wasm-release/web
```

## プログラム共通の状態保存

[状態保存の利用手順](../docs/user/machine-state.md)を参照してください。
CPU・RAM・周辺機器をブラウザー内に保存し、RTCは巻き戻さず別に扱います。

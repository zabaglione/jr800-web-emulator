# JR-800機械語サンプルとゲーム

JR-800の192×64ドットLCDに表示する、HD6301V1用の機械語サンプルです。
すべて付属のアセンブラーでビルドでき、通常のWebエミュレーターの「プログラムの読み込みと実行」で動きます。
各フォルダーの`main.s`がサンプル本体、`README.md`が個別の解説です。

| サンプル | 画面と操作 | 学べること |
| --- | --- | --- |
| [01 文字表示](01-hello/README.md) | `HELLO JR-800`などの3行を表示 | 文字コード、字形、サブルーチン |
| [02 市松模様](02-checkerboard/README.md) | 全画面に4×4ドットの模様を表示 | ビット操作、繰り返し、LCDの境界 |
| [03 10進カウンター](03-counter/README.md) | `00`から`99`まで数えて繰り返す | 比較、条件分岐、桁上がり |
| [04 跳ね返るスプライト](04-bounce/README.md) | 8×8ドットの図形が左右を往復 | 座標、方向、消去と再描画 |
| [05 テンキーカーソル](05-keypad/README.md) | テンキーの`4`で左、`6`で右へ移動 | キー入力、押下中の移動、画面端の制限 |
| [06 恐竜ゲーム](06-dino/README.md) | SPACEを押す長さでジャンプの高さを調整する | ソフトウェアPCG、可変ジャンプ、障害物の違い、衝突判定 |
| [07 RELIC DIVE](07-relic-dive/README.md) | 5・10・20階の下降専用ローグライク | 12種類の敵、資源管理、視界、少数キー、中断保存 |

## ビルドする

リポジトリのルートで、Native版のSDKとWASM版のエミュレーターを用意します。
必要な環境は[SDK開発ガイド](../../../docs/sdk/application-development.md)を参照してください。
次のコマンドはリポジトリのルートで実行します。

```sh
cmake --preset native-release
cmake --build --preset native-release
emcmake cmake --preset wasm-release
cmake --build --preset wasm-release
make -C sdk/examples/lcd
make -C sdk/examples/lcd test
```

生成先は`build/sdk-lcd/<サンプル名>/`です。

各サンプルのフォルダーでも、次の共通コマンドを使えます。

| コマンド | 動作 |
| --- | --- |
| `make` | ソースをアセンブルしてリンクする |
| `make run` | JR-800モデルで最初の画面まで実行し、`screen.svg`を保存する |
| `make debug` | 最初の画面の完成位置で止め、レジスターとシンボルを表示する |
| `make test` | 個別の動作を自動検査し、`verification.json`を保存する |
| `make clean` | そのサンプルのビルド生成物を削除する |

`make run`は画面を1枚出力するコマンドです。
アニメーションとキー操作は、次のWeb UIで確認します。
必要に応じて`JR8AS`、`JR8LD`、`NODE`、`WASM_DIR`を指定できます。
`WASM_DIR`の既定値は`build/wasm-release/web-module`です。

## Webエミュレーターで動かす

リポジトリのルートでローカルサーバーを起動します。

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory build/wasm-release/web
```

1. ブラウザーで`http://127.0.0.1:8000/`を開き、自分のJR-800 ROMを読み込みます。
2. BASICを起動し、画面が落ち着いてから「一時停止」を押します。
3. 通常画面で、ビルドしたサンプルを選びます。
4. 「プログラムの読み込みと実行」を押します。
5. BREAKキーでBASICへ戻ります。別のサンプルは、BASICへ戻ってから選び直します。

表示言語によってボタンの表記が異なります。
英語表示では`Load and run program`です。
「SDK application debugging」は合成RAM用なので、これらのLCDサンプルには使いません。

全7本でBREAKによるBASIC復帰に対応します。対象はJR-HuBASIC 1.0です。
終了時にBASICのプログラムと変数を初期化するため、必要な内容は起動前に保存してください。
もう一度実行する場合はサンプルを読み込み直します。
テンキーカーソルは、画面右側のテンキー、またはPCのテンキーの`4`と`6`で操作します。
文字キー側の数字`4`と`6`は別のキーです。

## 共通表示処理を読む

[common/display.s](common/display.s)は、画面を作るRAM領域とLCDへの転送を担当します。
CPUのAとBは8ビットの作業用レジスター、DはAを上位、Bを下位とする16ビットの組、Xは16ビットのアドレス用レジスターです。
`JSR`は戻り先をスタックへ保存して処理を呼び出し、`RTS`はその位置へ戻ります。

| 処理 | 入力と役割 |
| --- | --- |
| `init` | 8個のLCDコントローラーを初期化し、表示外の領域も消去する |
| `clear` | 1,536バイトの描画用RAMをゼロにする |
| `text` | Xに文字列の先頭、Dに描画先アドレスを渡して文字列を描く |
| `glyph` | AにASCII文字コード、Xに描画先を渡して1文字を描く |
| `present` | 描画用RAM全体をLCDへ転送する |
| `present_begin` | LCDへの分割転送を開始する |
| `present_next` | 46または50バイトを転送する。終了時はZフラグが1になる |
| `delay` | CPU命令のループで更新間隔を空ける |

画面1枚を表す描画用RAMを、ここでは**フレームバッファー**と呼びます。
1バイトが縦8ドットを表し、下位ビットが上側のドットになります。
横192バイトを1段として8段並べるため、必要量は`192 × 8 = 1,536`バイトです。
画面の左上を`x=0, y=0`とすると、格納先は`framebuffer + (y / 8の整数部分) × 192 + x`、バイト内の位置は`y % 8`です。

01〜06では、プログラムと固定データは`$2800–$3FFF`の範囲に配置します。
フレームバッファーは`$4000–$45FF`、サンプルの状態は`$4600–$46FF`、共通処理の一時変数はCPU内RAMの`$0080–$0091`です。
共通の終了処理は`$5400–$57FF`、BASICの退避領域は`$5800–$58FF`に確保します。
スタックポインターSPは各サンプルの先頭で`$5FFF`に設定し、下向きに使います。
RELIC DIVEは専用の[メモリー配置](07-relic-dive/README.md#構成とメモリー)を使用します。
LCDの表示外領域にBASICの表示が残らないよう、初期化では全コントローラーのRAMを消去します。

字形は[common/font.s](common/font.s)で新規作成した5×7ドットです。
描画にROMの文字パターンは使用しません。BASICへの終了処理は[common/basic.s](common/basic.s)でROMサービスを呼び出します。
`text`はゼロ終端のASCII文字列を受け取り、`glyph`は`$20–$5A`を範囲とします。
用意した字形は空白、ハイフン、数字、大文字英字で、そのほかの位置は空白です。
横幅は1文字6バイトなので、呼び出し側で文字列を1段192バイト以内に収めてください。
共通処理はA、B、Xを変更します。

LCDへの各書き込みではBUSY解除を確認します。ゲームでは`present_begin`の後に`present_next`を繰り返し、転送区間の間にもキーを読みます。
終了判定はキー処理より先に行い、転送途中では共通処理の作業領域とフレームバッファーを変更しないでください。

## 確認した結果と範囲

2026年9月6日に、基礎サンプル5本について次の検証を実施しました。
各フォルダーの`preview.svg`はエミュレーターのLCD出力から作った最初の画面です。

| 対象 | 自動検査 |
| --- | --- |
| 文字表示 | 最初の画面、HとXの字形、文字表の256バイト境界 |
| 市松模様 | 12,288ドットすべてが4×4の規則と一致、点灯6,144ドット |
| カウンター | 101画面で`00–99–00`、数値と表示字形の一致 |
| 跳ね返り | 95画面で両端の反転、座標、古い図形の消去 |
| キー操作 | 78画面で左右移動、両端での停止、キー解放、無関係なキー |

全276画面で、スタックの戻りと全ドットの転送結果も検査しました。
ROMを使わない独自の起動用データ、手元のJR-HuBASIC 1.0、JR-HuBASIC 2.0の3通りで同じ検査が通り、最初の画面はサンプルごとに一致しました。
Chromeの通常画面でも5本を読み込み、文字、全画面模様、数値の更新、図形の移動、テンキー操作を確認しました。

`make test`は既定で独自の起動用データを使用します。
これはROMを不要にするための小さなデータであり、実行本体は通常画面と同じC++製JR-800モデルです。
自分のROMでも検査する場合は、次のように絶対パスを指定します。

```sh
JR800_SAMPLE_ROM=/absolute/path/to/your-rom.j8r make -C sdk/examples/lcd test
```

`.rom`も指定できます。
ROMを指定した検査は通常画面と同様に未対応I/Oを無視する起動設定を使います。
ROMなしの検査はその設定を無効にし、サンプル自体が未対応I/Oに依存しないことを確認します。

LCDのアドレス選択とパネル配置は、既存の暫定モデルE-184〜E-186に依存します。
テンキーの入力値は所有者の実機観測E-381に基づきます。
実機での機械語実行、カセット転送、LCDの電気的タイミングは今回の検証に含みません。

追加の恐竜ゲームの操作と検証内容は、[06の解説](06-dino/README.md)を参照してください。
共通の`make`と`make test`には、このゲームも含まれます。

ブラウザー検査の再実行にはPlaywrightとChromeを使います。
サーバーを起動したまま、リポジトリのルートで実行してください。
最後に自分のROMへのパスを追加すると、BASIC起動後の読み込みも検査できます。

```sh
node tests/browser_lcd_samples_test.cjs http://127.0.0.1:8000/ build/sdk-lcd
```

結果は`build/sdk-lcd/browser-verification.json`、スクリーンショットは各サンプルの生成先の`browser.png`へ保存します。

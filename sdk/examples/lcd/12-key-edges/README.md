# 12 押下中・押下・解放を見分ける

テンキー5を使います。HELDは押下中、DOWNは押したフレーム、UPは離したフレームに1になります。下の数字は押した回数を0〜9で数えます。

## 使用する部品

新しいライブラリは **keys.s** のみです。ほかに共通のLCD表示・文字・BASIC復帰処理をリンクします。ライブラリの契約は[API解説](../../../lib/README.md)にあります。

## 実行

このフォルダーで次を実行します。SDKとWASMの準備、通常のWeb画面でのファイル読み込みは[共通ガイド](../README.md)を参照してください。

```sh
make
make run
make debug
make test
make clean
```

生成される実行ファイルはリポジトリの`build/sdk-lcd/12-key-edges/12-key-edges.j8a`です。BREAKでのBASIC復帰は既存のJR-HuBASIC 1.0用処理を使用します。09〜13の復帰を所有ROMや実機で新たに検証したものではありません。

## ソースを読む順序

1. `key_state`の3バイトは現在値・押下イベント・解放イベントです。
2. `keys_keypad`で読み、`saved_edges`へ表示用の値を保存します。
3. 押下イベントだけで回数を増やします。
4. `keys_ack`で処理済みイベントを消します。押下中の値は消えません。

キー処理の作業状態と表示用の状態を分けることで、イベントを消した後も、そのフレームの結果を表示できます。この入門例は1フレームに1回の走査です。短すぎる入力は取りこぼすので、DOWN/UPを見るときは少し長めに押してください。頻繁な走査とイベント保持の組合せは08と13を参照してください。

## 変更して試す

キー5のマスク`$20`をキー4の`$10`へ変更します。次にカウント条件を押下中へ変え、押しっぱなしで増え続ける違いを観察します。

## RAMと検証

実際の使用量はPROGRAM 970／STATE 7バイトです。PROGRAMにはコードと文字・画像などの固定データ、STATEにはライブラリを含む状態を数えています。共通して画面バッファー1,536バイト、復帰処理76バイト、退避・コピー用132バイト、CPU内作業領域18バイト、スタックが別に必要です。アドレス配置の予約範囲は使用量より大きいため、空き容量は`.map`を見て判断します。

押下・長押し・解放、1回だけの加算、9から0への循環を確認しました。 全画素のLCD転送とスタックも検査します。結果は`verification.json`、最初の画面は`screen.svg`です。実機とカセット転送は未検証です。

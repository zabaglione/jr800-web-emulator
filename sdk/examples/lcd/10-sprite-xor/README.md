# 10 背景を残すXORスプライト

8×8の図形が点模様の背景上を左右に往復し、縦位置も1ドットずつ変わります。操作は不要です。

## 使用する部品

新しいライブラリは **sprite.s** のみです。ほかに共通のLCD表示・文字・BASIC復帰処理をリンクします。ライブラリの契約は[API解説](../../../lib/README.md)にあります。

## 実行

このフォルダーで次を実行します。SDKとWASMの準備、通常のWeb画面でのファイル読み込みは[共通ガイド](../README.md)を参照してください。

```sh
make
make run
make debug
make test
make clean
```

生成される実行ファイルはリポジトリの`build/sdk-lcd/10-sprite-xor/10-sprite-xor.j8a`です。BREAKでのBASIC復帰は既存のJR-HuBASIC 1.0用処理を使用します。09〜13の復帰を所有ROMや実機で新たに検証したものではありません。

## ソースを読む順序

1. `background`で背景を一度だけ描きます。
2. `sprite_mode=1`を指定し、`draw`でXOR合成します。
3. 次のフレームで古い位置に同じ画像を描いて消し、座標更新後に新しい位置へ描きます。

背景の退避バッファーはありません。XORで消す前に背景を書き換えると復元できなくなるため、消去→背景更新→新位置への描画の順序を守ります。画像1バイトが縦8ドットで、bit 0が上です。

## 変更して試す

`image`の8バイトを変更して自分の図形にします。次に縦位置の式を変更し、8ドットの境界を越えても古い絵が残らないことを確認します。

## RAMと検証

実際の使用量はPROGRAM 1,019／STATE 15バイトです。PROGRAMにはコードと文字・画像などの固定データ、STATEにはライブラリを含む状態を数えています。共通して画面バッファー1,536バイト、復帰処理76バイト、退避・コピー用132バイト、CPU内作業領域18バイト、スタックが別に必要です。アドレス配置の予約範囲は使用量より大きいため、空き容量は`.map`を見て判断します。

370フレームで左右端の反転、全縦ずれ、XOR消去後の全背景ドットを確認しました。 全画素のLCD転送とスタックも検査します。結果は`verification.json`、最初の画面は`screen.svg`です。実機とカセット転送は未検証です。

# JR DINO 開発資料

遊び方は[README](README.md)を参照してください。

## ビルド

[共通の準備手順](../README.md)でNative版SDKとWASM版エミュレーターを用意し、リポジトリのルートで実行します。

```sh
make -C sdk/examples/lcd/06-dino
make -C sdk/examples/lcd/06-dino test
python3 -m http.server 8000 --bind 127.0.0.1 --directory build/wasm-release/web
```

`make run`は開始画面をSVGに出力し、`make debug`はレジスターとシンボルを表示します。

## 実装

HD6301V1の機械語で入力、ゲーム進行、描画を実行します。
JR-800固有の新たな機能やWeb側のゲーム専用キー変換は加えていません。
SPACEは`$0FEF`のbit 0を読みます。
描画とLCD転送の前後でも押下と解放を取得し、新規押下を次の更新で一度だけ消費します。
RETURNの読み取りやゲーム専用のホスト操作はありません。

ジャンプは初速7で始まり、更新ごとに上向き速度を1減らします。
SPACEを離した状態で上向き速度が3より大きいときだけ、速度を3に切り下げます。
1・2・3・4更新ぶん押した場合の最高点は13・19・24・28ドット、滞空は10・12・14・15更新です。
一度弱めた上向き速度は空中で押し直しても戻らず、着地後も新規押下が必要です。

障害物は3個のレコード（符号付き16ビットX座標・種類）で管理します。
最初は木箱・大岩・穴で、その後はLFSR疑似乱数から種類と80・88・96・104ドットの間隔を選びます。
通常の種類の重みはサボテンA・B・大岩が各1、木箱が3、穴が2です。
穴の後には56ドット先の大岩を選ぶ場合もあり、このときは通常の種類選択を上書きします。
初期位置と生成位置は192以上にし、すべて右端の外から入ります。
左へ抜けたレコードを最も右の障害物の先へ再配置し、最低位置192を守ります。
開始・再挑戦待ちの間も乱数を進め、同じ状態と同じ入力からは同じ結果を再現します。

当たり判定は見た目より内側です。サボテンは高さ14、大岩は18、木箱は7以上で回避します。
幅24ドットの穴は、足元の中心X=32が開口部にあり、高さが0になったときに落下します。
穴の描画は地面の線と砂利を消し、両端に縦の縁を描きます。落下はその場でゲーム終了とし、画面外への落下演出はありません。
移動量は1更新につき3・4・5ドットで、4更新につき1点を加えます。
スコアと最高記録は5桁の10進数字で99999に飽和させます。
速度決定用の内部距離は3桁で999に飽和し、100と200で速度を上げます。
記録の比較と保持も機械語プログラム内で実行し、エミュレーター側はゲームの内容を解釈しません。

## ソフトウェアPCG

[pcg.s](pcg.s)のRAM上の字形データをCPUで描画します。
専用PCG回路があると仮定した処理ではありません。
16×16ドットのパターンは1個32バイトで、全9個・288バイトです。

- 恐竜：歩行2個、空中、死亡。
- 障害物：サボテン2個、大岩、木箱。穴は地面の描画処理で表現。
- 背景：雲。

各列は上8ドットと下8ドットの2バイトで、下位ビットが上側です。
字形のコメントと`.byte`を対応させています。
`blit`はXにパターン先頭、Aに横座標、Bに縦座標を受け取ります。

恐竜は角・背びれ・曲がった尾を持つ独自のシルエットで、歩行・空中・死亡の全ポーズを揃えています。
READMEのキャラクターと障害物の画像は、実際のPCGデータから再生成できます。

```sh
make -C sdk/examples/lcd/06-dino images
```

## 検証

`make test`は、実エミュレーターへSPACEの押下・解放を送り、押す長さによる4種類のジャンプ軌道を検査します。
低いジャンプと高いジャンプを使い分けて走行距離999まで進み、全障害物と全速度を通ることを確認します。
穴と大岩の連続配置では、同じ踏み切り位置からの低いジャンプと高いジャンプを比較し、次のジャンプが間に合うかを検査します。
押しっぱなし、地上・空中でのRETURNの無効、最高記録の保持、穴への落下、短いSPACE入力も検査します。
分岐検査には通常のプレイから採取した状態保存を使い、ゲームのRAMや能力値を直接書き換えません。
各完成画面のLCDと描画バッファーの一致、スタックの復元、画面外での生成と速度どおりの水平移動を毎更新検査します。

Chromeでの実操作検査は、PlaywrightとChromeを用意して実行します。

```sh
node tests/browser_dino_test.cjs http://127.0.0.1:8000/ build/sdk-lcd/06-dino
```

結果はビルド先の`verification.json`と`browser-verification.json`に保存します。
LCDとキー入力の扱いは既存の暫定モデルに従います。
JR-800実機、SPACEの電気的な入力、カセット転送は今回の確認対象ではありません。

# 09 SEと単音メロディー

短い2音のSEと、休符を含む4音の旋律を交互に再生します。操作は不要です。

## 使用する部品

新しいライブラリは **sound.s** のみです。ほかに共通のLCD表示・文字・BASIC復帰処理をリンクします。ライブラリの契約は[API解説](../../../lib/README.md)にあります。

## 実行

このフォルダーで次を実行します。SDKとWASMの準備、通常のWeb画面でのファイル読み込みは[共通ガイド](../README.md)を参照してください。

```sh
make
make run
make debug
make test
make clean
```

生成される実行ファイルはリポジトリの`build/sdk-lcd/09-sound-sequence/09-sound-sequence.j8a`です。BREAKでのBASIC復帰は既存のJR-HuBASIC 1.0用処理を使用します。09〜13の復帰を所有ROMや実機で新たに検証したものではありません。

## ソースを読む順序

1. `effect`と`melody`を読む。1レコードは遅延回数と波形周期数の2ワード、周期数0で終了します。
2. `frame_ready`から`play`までを読む。画面を先に転送し、Xで音列表を選んで`sound_play`を呼びます。
3. `pause`を読む。音の間はBREAKを確認しながら待ち、表示を切り替えます。

音程はBASICのSOUND引数ではありません。計算方法は[音ライブラリ](../../../lib/README.md#seとメロディー)を参照してください。

## 変更して試す

`effect`の遅延回数を半分にし、音が高くなることを確認します。次に周期数だけを増やし、長さが変わることを確認します。

## RAMと検証

実際の使用量はPROGRAM 1,018／STATE 8バイトです。PROGRAMにはコードと文字・画像などの固定データ、STATEにはライブラリを含む状態を数えています。共通して画面バッファー1,536バイト、復帰処理76バイト、退避・コピー用132バイト、CPU内作業領域18バイト、スタックが別に必要です。アドレス配置の予約範囲は使用量より大きいため、空き容量は`.map`を見て判断します。

音列表2種類の切替とPort 1の892回の書き込みを確認しました。音の試聴ではなく論理波形の検査です。 全画素のLCD転送とスタックも検査します。結果は`verification.json`、最初の画面は`screen.svg`です。実機とカセット転送は未検証です。

再生中は描画とBREAK走査が止まります。BGMの並行再生ではありません。Port 1の出力値`$EF`とDDR `$10`は単独デモの設定で、他の機能との共用や実機の復帰時の影響は未検証です。

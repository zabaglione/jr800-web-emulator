# 13 STAR COURIER

3レーンの航路で隕石を避け、荷物を運ぶ短いアクションゲームです。キー入力、スプライト、帯スクロール、短いSEと終了時の曲を、JR-800の機械語で組み合わせています。ゲーム固有の処理はすべて`main.s`にあり、エミュレーター側の補助機能は追加していません。

## 遊び方

| テンキー | 操作 |
| --- | --- |
| 8 | 1レーン上へ移動 |
| 2 | 1レーン下へ移動 |
| 5 | 開始／シールド／リトライ |
| BREAK | 既存のJR-HuBASIC 1.0用処理でBASICへ戻る |

数字キーの長押しでは移動を繰り返しません。2レーン動く場合は一度離して、もう一度押します。

- `H`は耐久値です。初期値・上限は3、隕石に当たると1減り、0で敗北します。
- `E`はシールドの残り回数です。初期値・上限は3。5で1回分を使い、12更新の間隕石を防ぎます。シールド中の5は消費しません。
- 菱形の荷物は10点とシールド1回分、十字の修理アイテムは耐久値1を回復します。
- 被弾後は8更新の保護時間があり、連続被弾を防ぎます。
- 96更新ごとにセクターが進み、移動速度が3→4→5ドットになります。3セクターを生き残ると配達完了です。

点数は最大990点です。コースは24個の出現パターンを繰り返す固定配置です。ランダム生成ではないので、同じ操作を再現して動作を調べられます。通常は約30秒前後の航行ですが、音とフレーム処理の時間により変わります。

## ビルドと実行

```sh
make
make run
make debug
make test
make clean
```

準備は[共通ガイド](../README.md)を参照してください。実行ファイルはリポジトリの`build/sdk-lcd/13-star-courier/13-star-courier.j8a`です。通常のWebエミュレーターで読み込めます。

## ソースを読む順序

| 読む位置 | 担当 |
| --- | --- |
| `frame_ready` | 短い待ちとキー走査、更新、イベント消去 |
| `update` | タイトル／プレイ／敗北／クリアの切替、レーンとシールド操作 |
| `object_loop` → `collide` | 6個の物体の移動、重なり判定、回復とダメージ |
| `spawn`と`course` | 12更新ごとの物体生成、固定長の領域の再利用 |
| `render` → `draw_objects` → `draw_actor` | HUDと8×8画像の描画、LCD転送 |
| `pickup_se`、`hit_se`、`finish_tune` | 短いSEと配達完了の曲 |

1物体は`x, lane, type`の3バイトです。x=0は未使用です。6個で18バイトだけを使い、最も遅い速度でも再利用までに画面外へ出る間隔を設けています。当たり判定は同じレーンでの8×8矩形の横方向の重なりです。画像の透明部分まで細かく判定する方式ではありません。

テンキー8は`$0FFD`のbit 0、2と5は`$0FFE`のbit 2とbit 5から読みます。ゲーム内で3キーのビットをまとめ、共通の`keys_latch`へ渡します。4と6は移動に使いません。

入力はLCDの転送区間の間と、約3.3msずつの待ちの間で走査し、イベントを保持します。地面の星は1帯だけを左へ流し、空いた右端へ星を補充します。物体を描く部分は毎回消して描き直すので、背景退避用RAMは不要です。

## RAMと音の制約

| 用途 | 実使用量 |
| --- | ---: |
| プログラム・固定データ・共通表示コード | 2,275バイト |
| ゲーム状態＋ライブラリ作業領域 | 72バイト |
| 共有画面バッファー | 1,536バイト |
| BASIC復帰処理 | 76バイト |
| BASIC退避・コピー作業領域 | 132バイト |

上記合計は4,091バイトです。さらに共通表示のCPU内作業領域18バイトとスタックを使います。メモリーの予約範囲・空きの位置は`.map`を参照してください。二重画面、全画面の背景保存、動的なメモリー確保はありません。

SE中は機械語の更新とキー走査が止まります。荷物の音は約15ms、被弾音は約55ms、クリア曲は約0.44秒です。並行BGMは使いません。Port 1の出力・方向は08と同じ単独デモ用の設定で、実機の周辺機能との共用は未検証です。

## 確認した範囲

WASMのJR-800モデルで818フレームを実行し、毎回LCD全画素とスタックを確認しました。8/2でのレーン移動、4/6が移動に影響しないこと、端の制限、長押し、シールド消費、防御、被弾、修理、敗北、リトライ、3セクターのクリアを検査しています。荷物回収を狙うキー入力の実行では60点・耐久3でクリアしました。この自動操作は物体の状態を参照するため、人間が初見で遊んだ難易度評価ではありません。ゲームRAMを書き換えてクリアさせる処理はありません。

実機、所有ROMでのBREAK復帰、カセット転送、音の試聴は未検証です。

`make test`は`screen.svg`、`playing.svg`、`shield.svg`、`game-over.svg`、`clear.svg`と`verification.json`を生成します。検査スクリプトは[共通実行検査](../library-samples-check.mjs)です。

## 変更して試す

まず`course`を変えて、安全なレーンと荷物の位置を調整します。次に96更新のセクター長、12更新の出現間隔、3/4/5の速度を変更します。出現間隔を短くする場合は、6個の領域を再利用するときに前の物体が残っていないか確認してください。画像と衝突範囲を変更するときは、見た目だけでなく回避できる間隔も合わせて調整します。

# BASIC移行の実機テスト手順

目的は、JR-800実機のSAVEを録音したWAVが、Webで同じプログラムとして読み込めるか確認することです。
最初は短いプログラムを通常SAVEとASCII SAVEで1回ずつ録音してください。
この2本が通ったら、長いプログラムとカナ・GRAPHを確認します。
J8Aの現行仕様はバージョン1です。
ROMの1.0／2.0とは別の番号です。

手順1・4・5に相当する通常SAVE／ASCII SAVEを各2回録音した12本で検証しています。
確認済みの条件と制限は[対応範囲](compatibility.md)を参照してください。

## 用意するものと記録条件

- JR-800実機と、カセット出力に接続できる録音機器。
- 48 kHz、16ビット整数PCMのモノラルまたはステレオWAV。
- 実機のROMと、最新版をビルドしたWeb UI。
- LISTと実行結果を撮影する手段。

ZOOM H2nを使った実施例では、JR-800のマイク端子をH2nのLINE INへ接続し、ゲイン`6`で`SAVE`／`MSAVE`を録音しています。
再生側の接続と設定は[ZOOM H2nの実施例](compatibility.md)を参照してください。

録音を先に開始し、SAVEが終了して実機が入力待ちに戻ってから録音を止めます。
1ファイルに1回のSAVEを収め、先頭の信号や末尾を切らないでください。
MP3などへの圧縮、ノイズ除去、音声強調、自動音量調整をかけず、元のWAVを残します。
失敗時の切り分けに使うため、加工後のファイルだけを残すことは避けてください。

ROMの起動画面に表示される版、実機のRAM容量・増設の有無、録音機器、接続、録音レベルを記録します。
最初は実機と同じ版のROMをWebで使ってください。
別のROM版での読込は追加確認です。

## 1. 短いプログラムを2種類で保存する

実機の空いているBASICページへ、次のプログラムを入力します。
既存プログラムのあるページを使う場合は、先にその内容を保存してください。

```basic
10 REM SAVE TEST
20 DATA 12,34,"A:B"
30 READ A,B,A$
40 PRINT "BASIC OK"
50 PRINT A+B
60 PRINT A$
70 END
```

実機でLISTを確認・撮影してからRUNします。
期待する出力は次の3行です。
数値の前後の空白は判定から除きます。

```text
BASIC OK
46
A:B
```

プログラムを変更せず、次の2回を別々のWAVへ録音します。
実機が入力待ちに戻ったことを確認してから、次の録音へ進みます。

| 録音ファイル名 | 実機で入力するコマンド | Webで表示される種類 |
| --- | --- | --- |
| `short-bin.wav` | `SAVE "BINTEST"` | BASIC内部形式 |
| `short-text.wav` | `SAVE "TXTTEST",A` | BASICテキスト |

SAVEで実機側にエラーが出た場合は、その表示も記録します。
この段階ではWebの変換成否とは分けて扱います。

## 2. WAVをWebで直接読み込む

それぞれのWAVについて、次の手順を実施します。

1. 最新版のページを再読み込みし、実機と同じ版のROMで「BASICの起動」を押す。
2. BASICの入力待ちを確認し、「一時停止」を押す。
3. 「プログラム .WAV / .J8A」で録音したWAVを選び、「読み込む」を押す。
4. 種類と名前が上の表と一致すること、読込直後にプログラムを自動実行しないことを確認する。
5. 「実行を再開」を押し、LCD側をクリックしてからLISTを入力し、表示が終わるまで待つ。
6. 10〜70行があり、数値、文字列のコロン、REMの内容が実機のLISTと一致することを確認する。
7. RUNし、実機と同じ3行が出力されることを確認する。
8. 入力待ちで再び一時停止し、同じWAVを「読み込んで実行する」で読み込み、RUNを手入力せず同じ結果が出ることを確認する。

「読み込む」の直後はエミュレーターが停止しています。
LISTを入力する前に「実行を再開」を押してください。
SAVE形式によって内部のバイト数は変わるため、通常SAVEとASCII SAVEのサイズが同じである必要はありません。

## 3. J8Aへの変換も確認する

プロジェクトのルートで、同じWAVからJ8Aを作ります。
ここでは録音を非公開の`local-data/basic/`に置いた例を示します。
実際の保存先に合わせてパスを変更してください。

```sh
build/native-release/tools/jr8wav decode-native-program local-data/basic/short-bin.wav local-data/basic/short-bin.j8a
build/native-release/tools/jr8wav decode-native-program local-data/basic/short-text.wav local-data/basic/short-text.j8a
build/native-release/tools/jr8objdump local-data/basic/short-bin.j8a
build/native-release/tools/jr8objdump local-data/basic/short-text.j8a
```

変換が成功し、確認結果の先頭が`JR8APP 1.0`であることを確認します。
種類は通常SAVEが`basic-binary`、ASCII SAVEが`basic-text`です。
生成したJ8AをWebで読み込み、手順2と同じLIST・RUN・読込後実行を確認してください。
WAV直接読込とJ8A読込で結果が一致すれば、この組合せは合格です。

## 4. 長いプログラムを確認する

短い2本が通ったら、別の空きページに次を入力します。
長いASCII SAVEの複数ブロックと終端が、実機録音でも読み取れるかを確認するためのプログラムです。
同じ40文字の数字列を8行に入れています。

```basic
10 REM 0123456789012345678901234567890123456789
20 REM 0123456789012345678901234567890123456789
30 REM 0123456789012345678901234567890123456789
40 REM 0123456789012345678901234567890123456789
50 REM 0123456789012345678901234567890123456789
60 REM 0123456789012345678901234567890123456789
70 REM 0123456789012345678901234567890123456789
80 REM 0123456789012345678901234567890123456789
90 PRINT "LONG OK"
100 END
```

実機でLISTとRUNを確認し、`SAVE "LONGTXT",A`を`long-text.wav`へ録音します。
WebでWAV／J8Aの両方を読み込み、10〜100行が残ること、各REMの数字列が欠けないこと、RUNで`LONG OK`が表示されることを確認します。
LISTが画面に収まらない場合は、表示範囲を変えて確認してください。
余裕があれば、同じ内容を`SAVE "LONGBIN"`で`long-bin.wav`にも録音し、同様に確認します。

## 5. カナ・GRAPHの保存を確認する

別の空きページへ次を入力します。

```basic
10 PRINT "ABC"
20 PRINT "DEF"
30 END
```

実機のカナモードを使い、10行の引用符内のABCをカナ3文字へ置き換えます。
20行のDEFは、GRAPHモードで入力した図形3文字へ置き換えます。
引用符は残し、モードを解除してからLISTとRUNを確認・撮影してください。
使ったキーとSHIFTの有無も記録すると、文字コードの特定に役立ちます。

同じ内容を、通常SAVEの`SAVE "CHARBIN"`とASCII SAVEの`SAVE "CHARTXT",A`で別々に録音します。
ファイル名は`chars-bin.wav`と`chars-text.wav`とします。
WebでWAV／J8Aの両方を読み込み、LISTと実行結果の6文字が実機と同じ字形であることを確認してください。
Unicodeの見た目が近い文字へ置き換えて比較せず、実機写真を基準にします。

## 6. 既存ページと失敗時の状態を確認する

ページの保持を調べる場合は、Web側のページ1へ短い別プログラムを入れ、ページ2へ今回のファイルを読み込みます。
ページ2が正しく登録され、ページ1へ戻ると元の内容が残ることをLISTで確認してください。
読み込みは選択中のページを置き換えます。

読込エラーが発生した場合は、その直後に元のページをLISTし、読込前のプログラムが残っていることを確認します。
故意に失敗を作る追加検査では、正常なWAVのコピーから末尾を大きく削った別ファイルを使います。
元のWAVは残し、コピーを元と同じ名前で上書きしないでください。
エラー表示、読込前後のLIST、加工した範囲を記録します。

手順のASCII入力例3本は、エミュレーターのJR-HuBASIC 1.0／2.0で読込と実行を確認しています。
カナ・GRAPHへ置き換えた実機録音も、上記12本の検証で確認済みです。
手順6のページ保持・失敗時の確認は、この実機録音試験とは別の検査です。

## キーボード・RTCも比較する場合

BASIC移行の録音とは別に、次を追加確認できます。

- **CAPS.L、SHIFT、GRAPH、カナ**：実機とWebで同じモード・同じキーを使い、入力文字とモード表示を比較します。
  Webの仮想キーの字形も同じ文字を示すか確認してください。
- **起動時の現在日時**：Webで「ブラウザーの現在日時でBASICを起動する」をオンにします。
  `PRINT DATE$`、`PRINT TIME$`、`PRINT DAY$`で、端末のローカル日時・曜日と一致するか確認してください。
  これはWebの起動オプションであり、実機の自動同期を要求する検査ではありません。
- **DATE$と曜日の独立性（任意）**：実機の日時・曜日を先に記録し、`DATE$="26/09/05"`を設定して`PRINT DAY$`を確認します。
  確認したROMではDATE$だけで曜日は変更されませんでした。
  実機の結果を記録したら、元の設定へ戻してください。

RTCのうるう年レジスターへ直接書き込む実機試験、WAKEによるアラーム・復帰、カセットへの書き戻し、複数ファイルの連続テープは、この手順の合格条件に含めません。
日時とBASICの制限は[対応範囲](compatibility.md)を参照してください。

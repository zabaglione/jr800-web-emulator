# jr8objcopyで格納済みバイトを抽出する

`jr8objcopy`はJR8APPバージョン1またはJROバージョン1を検証し、明示した範囲だけを取り出します。

```sh
jr8objdump linked.j8a
jr8objcopy --segment 1 -o program.bin linked.j8a
jr8objcopy --section .data -o data.bin input.jro
jr8objcopy --image 0x0200 --size 256 -o image.bin linked.j8a
```

JR8APPの`--segment`には、`jr8objdump`が表示する10進の`SEGMENT`番号を指定します。
アプリ全体とSHA-256を検証してから出力を開きます。
DATAセグメントは格納バイトをそのままコピーし、アドレスの追加、再配置、独自ヘッダーの付加は行いません。

ZERO_FILLは論理サイズだけを持つため、`--segment`では拒否します。
範囲外番号、別形式、壊れた入力、入出力が同じパスの場合も、既存出力を変更する前に失敗します。

`--image`は開始アドレスと0より大きいサイズを要求します。
数値は10進または`0x`付き16進です。
半開区間は16ビット空間内に収まり、全アドレスがセグメントに属していなければなりません。
DATAはそのままコピーし、ZERO_FILLはゼロとして具体化します。
先頭、中間、末尾に未配置範囲があれば、推測値で埋めず拒否します。

JROの`--section`は、大文字・小文字を区別する完全一致でセクションを選びます。
`PROGRAM_BITS`でも再配置レコードがある場合は拒否します。
再配置前のオペランドを最終値として見せないためです。
`NO_BITS`は格納データを持たないので抽出できません。

成功時は何も表示しません。
引数とパスの誤りは終了状態2、無効な入力や抽出不能な選択は終了状態1です。

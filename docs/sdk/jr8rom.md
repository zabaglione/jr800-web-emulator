# jr8romでROMコンテナーを扱う

`jr8rom`は、アドレス付きJR8ROMバージョン1の作成、結合、検査、検証、抽出を行います。

```sh
jr8rom create -o owner.j8r \
    --segment 0x8000 rom-low.bin \
    --segment 0xC000 rom-high.bin
jr8rom combine -o combined.j8r rom-low.j8r rom-high.j8r
jr8rom inspect combined.j8r
jr8rom verify owner.j8r
jr8rom extract --address 0x8000 --size 32768 \
    -o logical-rom.rom owner.j8r
```

アドレスは10進、`0x`付き16進、`$`付き16進で指定できます。
`create`では各入力ファイルを、指定した16ビット論理アドレスの空でない1セグメントにします。
入力順にかかわらず出力順は一定で、隣接する入力の境界は保ちます。

全入力を読み、重複、16ビット範囲外、空ファイル、過大入力、入出力の同一パスを検査してから出力を開きます。
失敗しても既存の出力ファイルを途中まで書き換えません。

`combine`は2個以上のJR8ROMを完全に検証し、全セグメントをアドレス順へまとめます。
内容が同じでも範囲が重なれば拒否します。
どちらの取得結果を優先するかは推測しません。

`verify`は入力サイズを制限し、マジック、バージョン、フラグ、レコード順、範囲、重複、末尾、SHA-256を検査します。
`inspect`も同じ検証を行い、形式バージョン、セグメント数、各レコード番号、論理範囲、長さだけを表示します。
ROMバイト、ダイジェスト、入力パスは表示しません。

`extract`は開始アドレスと0より大きいサイズを要求します。
指定した半開区間の全アドレスが格納済みの場合だけ出力します。
複数の隣接セグメントをまたげますが、1バイトでも空きがあれば埋めずに拒否します。

作成、結合、検証、抽出の成功時は何も表示しません。
引数とI/Oの誤りは終了状態2、無効なセグメント、コンテナー、重複、未格納範囲は終了状態1です。

Web UIは`.j8r`に加え、従来から使われている32 KiBの`.rom`を読み込めます。
`.rom`はアドレスや完全性情報を持たないため、Web UIは`.j8r`への変換案内を表示して確認を求めます。
`jr8run jr800`は検証可能な`.j8r`だけを受け付けます。

WAVから直接`.j8r`を作る場合は、`jr8wav decode-native-msave`を使います。
完全な形式仕様は[JR8ROMアドレス付きROMコンテナー1.0](../formats/jr8rom-v1.md)を参照してください。
市販ROMを含む入力と出力はリポジトリへ追加しないでください。

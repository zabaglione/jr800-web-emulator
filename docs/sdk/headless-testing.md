# コマンドラインでJR8APPをテストする

`jr8run`は、JR8APPを命令数上限付きで実行し、結果を決定的なコマンドラインテストとして検査できます。
`--expect-stop`は停止理由、繰り返し指定できる`--expect`は終了時の状態を調べます。
指定した検査がすべて成立した場合だけ成功終了します。

```sh
jr8run \
  --max-instructions 100 \
  --watch write:0x0001 \
  --expect-stop memory-watchpoint \
  --expect 'PC == 0x020A && A == 0x99 && cycles == 12' \
  --expect 'mem8[0x0000] == 0x42 && mem8[0x0001] == 0x99' \
  program.j8a
```

条件式は、条件付きブレークポイントと同じC++コンパイラーと評価器を使います。
利用できる状態名は`PC`、`SP`、`X`、`A`、`B`、`CCR`、`cycles`、各フラグ`H`、`I`、`N`、`Z`、`V`、`C`です。
`mem8[address]`は、副作用なしで1バイトを調べます。
数値は10進数、`0x`付き16進数、`$`付き16進数に対応します。
算術、ビット、比較、等値、短絡論理演算を利用でき、識別子は大文字・小文字を区別しません。

一致するJR8DBGを`--debug`で渡すと、`symbol("exact.name")`でシンボルのアドレスまたは絶対値を取得できます。
シンボル名は大文字・小文字を区別し、自動的なメモリー参照は行いません。

すべての式はアプリを読み込む前にコンパイルします。
構文エラーが実行を途中まで進めることはありません。
評価結果が非ゼロなら成功、ゼロなら不成立です。
未知レジスター、読めないメモリー、0除算、不正なシフト、16ビット範囲外、見つからないシンボル、重複シンボルは、falseではなく評価エラーになります。
検査はトレースを増やさず、エミュレーター状態を変更しません。

Makefileでは16進数に`0x`表記を使ってください。
`$`はmakeが先に展開するため、使う場合は`$$`と書く必要があります。
旧`--expect-byte`はなく、メモリー検査も`mem8[...]`へ統一しています。

この検査機能は合成RAMで動くJR8APP向けです。
所有者のROMを使う`jr8run jr800`は別の実行モードです。

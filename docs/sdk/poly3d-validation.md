# poly3dと立体ゲーム試作の検証

2026-09-15。対象は`poly3d`、LCDサンプル15・16・18とゲーム[POLY DEFENDER](../../games/poly-defender/README.md)です。ゲーム進行・操作・判定・描画はJR-800の機械語で実行します。

## 実装と範囲

- 4頂点4三角形の三角錐、6頂点8三角形の八面体、8頂点12三角形の立方体を同じAPIで描画。
- Q7の2軸回転、平行投影、裏面除去、面法線による4段階の陰影、画面端の切り詰め。
- 水平・垂直線は縦8ドットのLCDバイトをまとめて処理。斜線は同じ走査線交点規則を使用。
- 描画器の作業領域は387バイト、フレームバッファーは1,536バイト1個。ゲームは標準RAM内に配置。
- 奥行きに応じた拡大率と表示順をゲームが管理。Zバッファー・透視投影・一般的な3D衝突判定は対象外。

APIとデータ形式は[ライブラリのREADME](../../sdk/lib/poly3d/README.md)、操作は[サンプル一覧](../../sdk/examples/lcd/README.md)にあります。

## Nativeの命令実行検査

Debug／Releaseの両方で次の6件が成功しました。

| 検査 | 内容 |
| --- | --- |
| `poly3d_library_test` | 5,328条件の座標変換・面判定・陰影・全画素を独立した式と比較。複数物体の白画素上書き、不正引数、斜線、864条件の水平／垂直線、上下文字欄と周辺メモリーの保護 |
| `sdk_library_test` | 既存の省RAM部品の回帰検査 |
| `lcd_sample_busy_test` | 全画面転送のBUSY確認 |
| `lcd_sample_incremental_busy_test` | 転送区間を分けたBUSY確認 |
| `lcd_dirty_busy_test` | 部分転送のBUSY確認 |
| `lcd_sample_basic_return_test` | BASICの状態退避、BREAK復帰処理の呼び出し順 |

描画器の単独検査の最大は224,674 Eサイクルでした。これはLCD転送を行わないRAMバス上の検査で、ゲーム全体のfpsには換算しません。

## WASMの実行検査

3本のサンプルとPOLY DEFENDERをWASM Debug／Releaseで検査しました。プロジェクトで新規作成した最小ブートROMを使う検査では、拡張RAMと未対応I/Oの無視を無効にしています。Releaseでは所有者提供のJR-HuBASIC 1.0でも同じ操作を実行し、BREAKで復帰処理へ入り、ROM側の実行へ戻ることを確認しました。

| サンプル | 検査フレーム数 | 主な操作・判定 |
| --- | ---: | --- |
| 15 POLY3D LAB | 235 | 各64方向、3モデル、陰影／線表示、2軸回転、自動回転への復帰 |
| 16 GATE FLIGHT | 445 | 入力による8ゲート通過、停止中の不変性、移動制限、HULL消費、失敗と再挑戦 |
| POLY DEFENDER | 2,069 | 敵の射撃・突進、アイテム回収と見送り、全武器段階、シールド、武器低下、分裂、ラッシュ、ボス撃破・強化攻撃、失敗と再挑戦 |
| 18 TURN MATCH | 79 | 入力による3問正解、正解時の2物体の画素一致、誤答、長押しの非連続回答、角度の周回、再挑戦 |

毎フレーム、LCDの全12,288画素とフレームバッファーの一致、SP=`$5FFF`、描画器のエラーなし、コードの不変性、周辺RAMの保護を確認します。自動プレイは実際のキー状態だけを入力し、ゲーム内の状態・得点・座標をメモリー書き込みで操作しません。テストから状態を読み取ることは、検査と入力選択にのみ使います。

Native Debug／Releaseのアセンブラー・リンカーから生成した4本のJ8Aはバイト単位で一致しました。POLY DEFENDERは同じ2,069フレームをNativeでも再生し、WASMとのサイクル・画面・状態の一致を確認しました。

## 速度とRAM

WASM Release、最小ブートROM、既存JR-800モデルでの結果です。速度は公称1,228,800 Eサイクル/秒で換算します。初期画面の全転送やクリア／終了画面への切替を除いた、各テストの連続区間を使用しています。入力走査・通常のLCD部分転送・更新待ちを含みます。

| 場面 | 区間フレーム数 | 平均Eサイクル/更新 | 公称クロック換算 |
| --- | ---: | ---: | ---: |
| 三角錐の自動回転 | 64 | 83,930 | 14.64fps |
| 八面体の自動回転 | 64 | 125,976 | 9.75fps |
| 立方体の自動回転 | 64 | 197,049 | 6.24fps |
| ゲート飛行 | 284 | 133,397 | 9.21fps |
| POLY DEFENDER | 714 | 120,235 | 10.22fps |
| 回転パズルの操作 | 50 | 129,611 | 9.48更新/秒 |

ゲート飛行は水平・垂直線のバイト処理により、同じ自動プレイ区間で171,145→133,397 Eサイクル/更新、7.18→9.21fpsへ改善しました。画像の格納やエミュレーター高速化による改善ではありません。

描画・転送・画面切替を含む入力走査の観測最大間隔は、15が11,855、16が30,024、POLY DEFENDERが43,317、18が30,247 Eサイクルでした。既存ブラウザーの最小キー保持49,152 Eサイクルと、入力用カウンターの1周65,536 Eサイクルより短い値です。これは観測した操作経路の値で、実機のBUSY待ちや任意の自作メッシュに対する保証ではありません。

| サンプル | コード・固定データ | 描画面 | ゲーム・共通状態 | BASIC復帰コード＋退避 | 配置合計（スタック除く） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 15 | 4,154 | 1,536 | 450 | 208 | 6,348 |
| 16 | 4,735 | 1,536 | 466 | 208 | 6,945 |
| POLY DEFENDER | 8,269 | 1,536 | 568 | 208 | 10,581 |
| 18 | 4,571 | 1,536 | 455 | 208 | 6,770 |

単位はバイトです。上記以外に既存LCD処理のCPU内RAM `$80–$91`とスタックを使用します。リンク用に予約した領域の容量と、実際の配置バイト数は別です。

## ブラウザーの目視・操作確認

ローカルの通常Web UIと所有者提供ROMを使用し、CUAによるファイル選択と仮想キー操作で確認しました。

- 標準のJ8A読み込み、モデル切替、BREAKによる空のBASICへの復帰。
- ゲート飛行の開始とゲーム内一時停止。
- 射撃ゲームの開始・発射、HULL LOST、RETURNによる再挑戦。
- 回転パズルの誤答表示、3回の方向操作で見本と同じ向きになること、SPACEで次の問題へ進むこと。
- ブラウザーの警告・エラーログは空。液晶の不明ドットは0。

各試作のプレビューは、エミュレーターが生成したLCD画素から保存したSVGです。キーボードやBASICのROM由来字形はプレビューに含めていません。

## 再実行と限界

各サンプルの`make test`は`build/sdk-lcd/<名前>/verification.json`を出力します。`WASM_DIR`、`JR8AS`、`JR8LD`、`BUILD_DIR`でDebugの環境と出力先を指定できます。所有するROMを`JR800_SAMPLE_ROM`で指定すると`verification-owned-rom.json`へ記録します。ゲームは`make -C games/poly-defender test`で検査し、`build/games/poly-defender/`へ結果とNative用の`replay.txt`を出力します。ゲームの所有ROM検査には`JR800_GAME_ROM`を使います。ROM自体をリポジトリへ追加しないでください。

実機での実行、LCDの残像や電気的タイミング、同じ行のキー同時押し、カセット転送は未検証です。

## POLY DEFENDER横スクロール版（2026-09-15）

自機を左側に置き、敵が右側から接近する構成です。テンキー8／2・W／Sで上下に動きます。敵は右端の小さい姿から12更新かけて拡大・前進し、登場中は攻撃・被弾しません。狙った高さへ32更新で進む固定弾道の敵弾に対して、移動する時間を確保しています。

開始・クリア・ゲームオーバーのジングル、敵味方の発射、命中・爆発・分裂・取得・防御・被弾の音を追加しました。ボスの前には文字と動く枠による警告、警告音、その後に拡大・接近する演出があります。被弾時は敵・弾・自機を止め、全画面反転、衝突位置のX、BOLT／ENEMYの原因表示を行います。最後の撃墜は数秒残してからゲームオーバーへ移ります。

音は既存の`sound.s`を使用するPort 1 bit 4のソフトウェア出力です。SEは待ち時間中に短い断片を再生し、ジングル・警告・撃墜音は表示済み画面を保持して最後まで鳴らします。断片間に入力とBREAKを走査します。割り込み音源、同時BGM、新しいハードウェア経路を仮定していません。ライブラリ本体・共通ランタイム・エミュレーターのホスト側に変更はなく、ゲームのMakefileが音の部品を追加リンクします。

固定方向の自機を7本の水平区間で描くことで、同じ形の座標変換・面処理を繰り返す負荷を削減しました。敵の陰影付き立体は毎フレーム`poly3d`で変換・描画します。敵最大2体、味方弾・敵弾各2発、アイテム1個の上限は維持しています。

| 区間 | 更新数 | 平均Eサイクル | 最大Eサイクル | 公称クロック換算 |
| --- | ---: | ---: | ---: | ---: |
| PATROL | 191 | 119,884 | 146,256 | 10.25fps |
| SPLIT | 116 | 121,271 | 162,874 | 10.13fps |
| RUSH | 227 | 120,279 | 146,046 | 10.22fps |
| BOSS | 180 | 119,884 | 147,041 | 10.25fps |
| ラッシュ負荷検査 | 327 | 120,462 | 142,649 | 10.20fps |

通常プレイは714更新、平均120,235 Eサイクル、10.22fpsです。演出中の意図的な画面保持と場面切替を除き、旧試作の平均123,624・最大188,366 Eサイクルを超えると検査が失敗します。ゲーム内容が同じ比較ではありません。

Native Debug／Releaseのツールが生成したJ8Aは一致し、WASM Debug／Releaseおよび所有者提供JR-HuBASIC 1.0で各2,069フレームの検査が成功しました。全画素・スタック・周辺RAMに加え、上下移動限界、入口での保護、固定弾道、分裂、全武器段階、シールド、強化の見送り、OPEN中の追加ダメージ、低HP攻撃、再挑戦初期化を確認しています。弾と敵本体による被弾を別に発生させ、停止中のゲーム状態の不変性と反転の全画素一致も検査します。警告枠の更新で囲まれた文字が消える不具合は、毎更新の文字画素比較で回帰検査します。13種類の音イベントを観測しました。

入力走査の最大間隔は43,317 Eサイクルです。音の断片も含み、既存ブラウザーの最小キー保持49,152とカウンターの1周65,536 Eサイクルより短く収まっています。コード・固定データ8,269、描画面1,536、ゲーム・共通状態568、BASIC復帰関連208バイト、合計10,581バイト（スタック除く）です。実機の待ち時間・音色・LCD残像を保証する値ではありません。

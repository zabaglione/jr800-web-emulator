# ゲームの検証記録

2026-09-11のパズル拡充・奥行き表現・数字書体更新を対象とする、エミュレーター上の結果です。実機性能、実機のLCD応答、カセット転送の証明ではありません。

## 今回の変更と確認範囲

- 15作品を各40面、合計600面に更新しました。全600面で通常クリアと追加目標を含むクリアの両方を、実際のキー入力で確認しました。1・2・3の星評価、最高評価の保持、戻し・再挑戦、規定手数超過も検査しています。
- 5文字の面コードと25文字の全評価コードを実装しました。全作品・全40面の符号化、40面すべての未クリア／星1〜3の復元、別作品・文字範囲・長さ・検査値エラー時に状態を変えないことを検査しています。実キーを使った入力・取消・復元も確認しました。
- 全50作品を見直し、15作品のタイトル、13作品のゲーム中の素材に奥行きを追加しました。23作品の数字を計器風・活字風・丸みのある書体へ差し替えました。原寸の全作品と整数倍表示を目視確認しています。[作品別の判断](depth-design.md)に、採用した効果と平面表示を保った理由を記録しました。
- 全50本のWASM Release操作再生が成功しました。同じ入力をNativeで再生し、合計373,398フレームのCPUサイクル・画面ハッシュ・LCD転送数・画面状態を照合しました。
- 所有するJR-HuBASIC 1.0 ROMでも全50本の操作再生が成功しました。WASM Debugでは全50本の起動・最初の操作・メニュー停止・復帰を確認しました。
- 直接起動とBASICのCALL起動、50本×2通りの100ケースでBREAK復帰を確認しました。空のBASIC、計算結果のLCD表示、新規BASICプログラムの実行、日付の保持、再ロードしてプレイ中からの2回目の復帰を検査しています。
- タイトルとゲーム中3場面の200場面に、15作品の面選択画面を追加しました。計215場面、原寸と4倍の430枚を実行中のLCDから撮影しています。

Native Debug／Releaseの必要なチェックを実行し、公開候補のNative Releaseは63項目が成功しました。WASM Debugは115項目が成功しました。WASM Releaseは113項目が最初の一括実行で成功し、新しいレンガ形状に期待値を更新したWALL BREAKの2項目も、同じコマンドで個別に再実行して成功しました。公開用ソースから生成したJ8Aは、全50本で検証した実行ファイルとバイト単位で一致しています。

ローカルChromeで全50本の保存ROM復元・自動起動・タイトル画素・実キーと仮想キー・音声開始・再読み込みを確認しました。ROM未設定、不明ID、整合性検査失敗、通常アクセス時の手動起動も検査し、ROMを送信するHTTP要求がないことを確認しています。

## 描画と操作

再生の各フレームで、LCDの12,288画素を1,536バイトの描画面と比較します。静止したタイトル・盤面・停止メニュー・パスワード画面ではLCDデータ転送が0バイトであることを検査しています。

HUDの検査は4系統の数字の原画と、通常・縦長・横幅のある数字・小さい数字を対象にします。全0〜9の数字、0〜65535の桁変化、反転、古い数字の消去、コントローラー境界、同値の再描画抑止を含みます。HPゲージの尺度・上限・消去、左右に移動したプレイ領域の保護、星・USED・PARを含む結果表示とその外側の画素保護も検査しました。

共通LCD検査はBUSYを0・1・8回の読み取りで遅延させ、画面端とコントローラー境界を含む部分転送を全画面と比較します。入力はテンキーとWASDを論理方向にまとめてから押下を判定します。600面の検査は面ごとに両方式を交互に使います。短い入力、長押し、同方向の重複、SPACEの非リピート、画面切替時のキー解放を既存の検査で確認しています。

WALL BREAKのレンガ・球・パドル、BEAT STEPの矢印、BALANCE DOCKの荷物などは、独立して再構築した表示とも比較します。奥行きは元の素材の寸法内に収まり、論理座標と当たり判定を変えません。

## ゲームの規則

パズルの解答は[チャレンジ設計](puzzle-design.md)で説明する独立したモデルと照合します。箱押し・光路と循環・氷の停止・扉と鍵・配管の漏れ・数字の合流・地雷の推理・輪の閉鎖・ナイトとペグの跳躍・敵の行動・工場の加工と出荷を確認します。通常クリアの時点で評価を確定し、追加目標を後から回収して評価を変えることはできません。

ほかの35作品も既存の規則検査とキー入力再生を実行しました。盤上ゲームの合法手とCPU、カード12種類の効果と山札、ダイスの得点、移動体と弾の接触、探索の資源、鉄道の合流、農作業と交易、弾道・ゴルフ・対戦とタイミングを対象にします。失敗・再挑戦やクリア後の進行も各作品の検査に含まれます。

自動操作は検証用で、人間の初見プレイの難易度を証明するものではありません。ゲームの規則・乱数・成長・得点・パスワードはJR-800側で実行します。

## RAMと実行時間

標準RAM内でBASICの作業領域を保持する[配置](visual-design.md)を使います。最大割当は13,471バイト、検証経路での最大スタック使用は14バイトです。別途512バイトのスタックを予約します。これらの測定は全操作の最大値を保証するものではありません。

RAMはコード・画像・ゲーム状態・描画面・BASIC復帰領域の合計で、CPU内部の共通作業領域は別です。Eクロック1,228,800Hzによる換算です。「最大更新」は画面切替も含み、「プレイ更新」はゲーム進行中の更新です。

## 対応環境と再現

拡張RAMを無効にした検証は、独自の最小起動コードを使用します。所有ROMの起動は既存のBASIC実験プロファイルを使います。JR-HuBASIC 2.0・実機操作・実際の発音品質は対応確認に含めません。音声のブラウザー検査は再生データの供給までです。

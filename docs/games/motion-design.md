# 移動の途中表示とクリア演出

2026-09-11更新。演出・入力・音はJR-800プログラム側で処理します。

## 途中を表示する操作

| 作品 | 表示する途中経過 | 判定と操作 |
|---|---|---|
| ICE ROUTE | 氷上を1マスずつ滑走 | 滑走全体で1手。途中の収集、停止、1手戻しに対応 |
| LINE FOUR | 人間とCPUのディスクが上から1段ずつ落下 | 着地時に勝敗判定。1手戻しはCPUの応手も戻す |
| NUMBER RAIL | 数字が隣のマスへ寄り、同値の数字が合流 | 合流済みの数字は同じ操作中に再合流しない。停止後に新しい数字を1個出す |
| PIPE WEAVE | Sから接続先へ水が広がる | 回転後に経路を再計算し、水の到着を順に表示する。漏れと出口の判定を維持 |
| STEP STRIKE | 自分の弾が射程内のマスを順に通過 | 射撃全体で1手。表示が終わってから敵弾とターンを1回だけ進める |

途中表示はCPUサイクルに基づく共通タイマーで進めます。ICE ROUTEは1マス5刻み、LINE FOURとSTEP STRIKEは4刻み、NUMBER RAILとPIPE WEAVEは3刻みです。1刻みは公称約16msで、描画処理が長い場面では実際の表示間隔も長くなります。RETURNメニュー中は進行を止め、再開時に待ち時間を取り直します。

ARC DUEL、RICOCHET OPS、WIND PUTTなど、弾や球の飛行を既に順次表示する作品は、その方式を維持しています。隣接マスへの歩行、駒の配置・反転、カードの選択などには新たな移動待ちを設けていません。ナイトやペグの跳躍も盤上の一手として扱います。

## クリアした盤面と音

全50作品で、完成した盤面を残してジングルを鳴らしてから結果を表示します。ICE ROUTEは専用ポーズを含む固有の演出で、ほかの49作品は共通の約1.5秒の演出です。7音の旋律を8ジャンルごとに用意し、最後の音と短い無音区間で余韻を作ります。

完成した盤面は描き直さず、保持中のLCD転送は0バイトです。発音を2周期ずつに分けてキー走査を挟みます。結果画面が出てからSPACEで続行し、押しっぱなしでは次の面へ進みません。BREAKによるBASIC復帰は演出中も利用できます。

共通演出は既存の音符管理領域を再利用し、追加状態は2バイトです。第2フレームバッファーは使いません。作品別のRAM割当・スタック・更新時間は[検証記録](validation.md)に掲載しています。

## 人型の向き

BOX SHIFTのプレイヤーと、STEP STRIKEのプレイヤー・敵には、横方向のドット列を縦方向のLCD列として渡す誤りがありました。上から下へ読めるドット原稿を用意し、LCD用の列データへ変換して修正しました。STEP STRIKEは人型を直立させたまま、射撃方向の印を上下左右へ付けます。

原寸と整数倍表示で確認し、実行中のLCDの画素から頭が上、足が下にあることも検査します。ほかの人型は座標指定の原稿を確認しました。上から見た機体など、ゲームの方向を示す向きは維持しています。

## 検証方法

[途中表示の検査](../../games/tools/motion_check.mjs)で、落下が行を飛ばさないこと、数字の総量が合流中に保存されること、水が接続先へ到達すること、射撃中に敵の時間が進まないこと、メニュー中の停止を確認します。従来の独立した規則モデルとの照合も継続します。

[共通の実行検査](../../games/tools/harness.mjs)では、クリア中の盤面保持・無転送・7音の進行・押しっぱなしによる誤決定防止を確認します。[ブラウザー検査](../../tests/browser_game_motion_test.cjs)では、通常のキー操作から4作品をクリアし、Canvas上の途中表示、完成盤面を残す時間、Web Audioへ渡される音声の変化を確認します。ブラウザー検査はPlaywrightとChromeを使用します。

これらはエミュレーター上の検査です。実機のLCD応答、音、転送・実行については未検証です。

# JRO再配置可能オブジェクト形式1.0

## 用途

JROは`jr8as`、`jr8ld`、オブジェクト調査ツール、デバッグ情報生成の間で受け渡す再配置可能オブジェクト形式です。
プロジェクトや利用者が作成した命令列とメタデータだけを格納し、JR-800のROMは格納しません。

標準拡張子は`.jro`、形式名とマジック識別子は`JRO`です。
バージョン1.0は次の情報を表現します。

- データ保持セクションとゼロ初期化セクション
- 属性、アラインメント、任意の固定配置
- local／global、section／absolute／undefinedシンボル
- 明示的な加数を持つ再配置
- パスとSHA-256で識別するソースファイル
- セクション範囲とソース位置の対応
- 完全一致で扱うCPUプロファイル名
- producer、version、決定的なbuild ID

特記のない整数は符号なしビッグエンディアンです。
文字列はビッグエンディアン`u32`のバイト長と、NULを含まない正しいUTF-8で表します。
表のインデックスは0始まりです。
未知の列挙値、非ゼロの予約領域、不正な参照、正しくないUTF-8、末尾の余分なデータ、重複範囲は拒否します。

## ヘッダーと表の順序

ホストのポインター、パディング、プラットフォームABI値は保存しません。

| フィールド | エンコード |
| --- | --- |
| magic | `4A 52 4F 00`（`JRO\0`） |
| major version | `u16`。1 |
| minor version | `u16`。0 |
| header flags | `u32`。ゼロ |
| target CPU profile | `mc6801`や`hd6301v1`などの小文字文字列 |
| producer | 空でない文字列 |
| producer version | 空でない文字列 |
| build ID | SHA-256の32バイト |
| source-file count | `u32` |
| section count | `u32` |
| symbol count | `u32` |
| relocation count | `u32` |
| source-line count | `u32` |

後続の表は、ソースファイル、セクション、シンボル、再配置、ソース行の順です。
各表は最大65,535レコード、文字列は最大65,535バイト、セクションは最大65,536論理バイト、ファイル全体は最大64 MiBです。

CPUプロファイル名は完全一致で扱います。
`jr800_unresolved`を`hd6301v1`として代用してはいけません。
build IDは、producerが正規化したビルド入力に対して計算したSHA-256です。
ソースレコードのSHA-256は、実際に使用したソース内容を識別します。

## ソースファイルレコード

| フィールド | エンコード |
| --- | --- |
| path | 空でない文字列 |
| content SHA-256 | 32バイト |

パスはオブジェクト内で一意です。
再現可能な論理パスを利用でき、実機上の絶対パスである必要はありません。

## セクションレコード

| フィールド | エンコード |
| --- | --- |
| name | 空でない一意の文字列 |
| type | `u8`。1は`PROGRAM_BITS`、2は`NO_BITS` |
| attributes | `u8`。bit 0はallocate、bit 1はwrite、bit 2はexecute |
| placement | `u8`。0はrelocatable、1はfixed |
| reserved | `u8`。ゼロ |
| alignment | `u32`。1～65,536の2のべき乗 |
| fixed address | `u32`。relocatableではゼロ、fixedでは0～65,535 |
| logical size | `u32`。最大65,536 |
| data size | `u32` |
| data | `data size`バイト |

`PROGRAM_BITS`ではdata sizeとlogical sizeが一致します。
`NO_BITS`ではdata sizeがゼロです。
fixedセクションは16ビット空間内に完全に収めます。
ほかの表がセクション番号を参照するため、セクション順は意味を持ちます。

## シンボルレコード

| フィールド | エンコード |
| --- | --- |
| name | 空でない一意の文字列 |
| binding | `u8`。1はlocal、2はglobal |
| definition | `u8`。1はsection、2はabsolute、3はundefined |
| reserved | `u16`。ゼロ |
| section index | `u32`。section以外は`FFFFFFFF` |
| value | `u32`。セクションオフセットまたは絶対値 |
| size | `u32` |

sectionシンボルの範囲は対象セクション内に収めます。
サイズ0のラベルはセクション末尾にも置けます。
absoluteシンボルはセクションを持たず、0～65,535の値とサイズ0を持ちます。
undefinedシンボルはglobalで、セクションを持たず、値とサイズはゼロです。
再配置がシンボル番号を参照するため、シンボル順は意味を持ちます。

## 再配置レコード

| フィールド | エンコード |
| --- | --- |
| section index | `u32` |
| offset | 再配置フィールドのバイト位置`u32` |
| type | `u8` |
| reserved | ゼロ3バイト |
| symbol index | `u32` |
| addend | 2の補数、ビッグエンディアン`i32` |

再配置先は`PROGRAM_BITS`でなければなりません。
参照するセクションとシンボルは存在し、再配置フィールドはセクション外やほかの再配置と重複してはいけません。

`S`を解決済みシンボルアドレス、`A`を符号付き加数、`F`を再配置フィールドの最終アドレス、`W`をフィールド幅とします。

| 値 | 名前 | 幅 | 計算と検査 |
| ---: | --- | ---: | --- |
| 1 | `ABS8` | 1 | `S + A`を書き込み、0～255を要求 |
| 2 | `ABS16_BE` | 2 | `S + A`を上位、下位の順に書き込み、0～65,535を要求 |
| 3 | `REL8` | 1 | `S + A - (F + W)`を書き込み、-128～127を要求 |
| 4 | `DIRECT8` | 1 | `S + A`を書き込み、direct pageの0～255を要求 |

再配置は`(section index, offset, type, symbol index, addend)`順で保存します。
バージョン1.0は`HI8`と`LO8`を定義しません。
明示的な上位／下位抽出構文がない状態で切り捨てを許すと、オーバーフローを隠すためです。

## ソース行レコード

| フィールド | エンコード |
| --- | --- |
| section index | `u32` |
| offset | `u32` |
| length | 0より大きい`u32` |
| source-file index | `u32` |
| line | 1始まりで0より大きい`u32` |
| column | 不明なら0、それ以外は1始まりの`u32` |

範囲はセクションの論理サイズ内に収めます。
同じセクション内の対応範囲は重複できません。
保存順は`(section index, offset, length, source-file index, line, column)`です。

## 決定性とバージョン

ライターは出力前に意味モデルを検証し、再配置表とソース行表を正規順序へ並べます。
インデックスに意味があるセクション、シンボル、ソースファイルの順序は呼び出し側が決めます。
同じ検証済みモデルからは、時刻やホストパスを自動追加せず、同じバイト列を出力します。

major versionの変更は非互換です。
初期リーダーは1.0だけを受け入れ、それ以外を明示的に拒否します。
旧形式へのフォールバックやbest effort復旧は行いません。

# JR8APPロード可能アプリケーション形式バージョン1

## 用途

JR8APPは`jr8ld`が出力する、配置アドレス付きの実行用ファイルです。
プロジェクトで作成したデータとゼロ初期化範囲だけを格納し、JR-800のROMは格納しません。

標準拡張子は`.j8a`、形式名とマジック識別子は`JR8APP`です。
特記のない整数は符号なしビッグエンディアン、文字列はNULを含まない長さ付きUTF-8、アドレスは16ビットCPU空間として扱います。

## ヘッダー

| フィールド | エンコード |
| --- | --- |
| magic | `JR8APP`の後ろにゼロ2バイトを付けた8バイト |
| version | `u16` major、`u16` minor。バージョン1.0 |
| flags | `u32`。バージョン1ではゼロ |
| target profile | 長さ付き文字列 |
| entry point | `u16` |
| reserved | `u16`。ゼロ |
| integrity SHA-256 | 32バイト |
| segment count | `u32` |

完全性ダイジェストは、対象プロファイル、エントリーポイント、正規化済みセグメントを結び付けます。
ダイジェスト入力は`JR8APP-INTEGRITY-V1`とゼロ1バイトから始まり、対象プロファイルのバイト長`u32`、プロファイル本体、エントリーポイント`u16`、セグメント数`u32`、各セグメントの種類`u8`、アドレス`u16`、論理サイズ`u32`、格納データの順です。

## セグメントレコード

| フィールド | エンコード |
| --- | --- |
| kind | `u8`。1はDATA、2はZERO_FILL |
| reserved | `u8`。ゼロ |
| address | `u16` |
| logical size | `u32` |
| stored size | `u32` |
| data | `stored size`バイト |

DATAセグメントは論理サイズと同じバイト数を格納します。
ZERO_FILLセグメントはデータを格納しません。
セグメントはアドレス昇順で、空でなく、重複せず、末尾が`$10000`を越えてはいけません。
エントリーポイントは、いずれかのセグメント内に置きます。
ローダーはDATAをコピーし、ZERO_FILLをゼロで初期化します。

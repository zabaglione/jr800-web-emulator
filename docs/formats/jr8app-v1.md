# JR8APPロード可能プログラム形式バージョン1

拡張子は`.j8a`、識別名は`JR8APP`です。
機械語、BASICテキスト、BASIC内部形式を一つのコンテナーで扱います。
ROMや実行途中のCPU・周辺機器の状態は格納しません。
BASIC対応を含む現行の構造はバージョン1.0です。

整数は符号なしビッグエンディアンです。
プロファイルは長さ付きUTF-8ですが、プログラム名とBASIC本体はJR-800の元の文字コードを保持します。

## 共通ヘッダー

| フィールド | エンコード |
| --- | --- |
| magic | `JR8APP`とゼロ2バイト。合計8バイト。 |
| version | `u16` major=1、`u16` minor=0。 |
| kind | `u8`。1=機械語、2=BASICテキスト、3=BASIC内部形式。 |
| target profile | バイト長`u32`とUTF-8文字列。現在の対象は`hd6301v1`。 |
| name length | `u8`、0〜16。ゼロは名前なし。 |
| name | 指定長の元の文字コード。`$00`〜`$1F`を含めない。 |
| integrity SHA-256 | 32バイト。 |
| body | 種類ごとに定義する本体。 |

完全性ダイジェストの入力は、`JR8APP-INTEGRITY-V1`とゼロ1バイト、`kind`から`name`までの直列化結果、`body`の順です。
機械語のセグメントはアドレス順に正規化してから計算します。
形式、名前、内容のいずれの変更もダイジェストに反映されます。
不明な種類、未対応バージョン、旧構造、余分な末尾、不正な長さ、ダイジェスト不一致は拒否します。

## 機械語の本体

最初に実行アドレス`u16`、セグメント数`u32`を格納します。
各セグメントは次の順序です。

| フィールド | エンコード |
| --- | --- |
| segment kind | `u8`、1=DATA、2=ZERO_FILL。 |
| address | `u16`。 |
| logical size | `u32`。 |
| stored size | `u32`。 |
| data | `stored size`バイト。 |

DATAは論理サイズと同数のバイトを格納し、ZERO_FILLは格納サイズを0にします。
セグメントは空でなく、重複せず、16ビットアドレス空間内に収めます。
データ保存用のMSAVEでは、実行アドレスがセグメントの外でもその値を保持します。
ローダーは実行の有無を別に受け取り、読込だけの場合はPCを変更しません。実行を要求する場合は実行アドレスがセグメント内にあることを確認し、範囲外ならRAMを書き換える前に拒否します。SDKのリンカー出力も実行可能なアドレスを要求します。

## BASICの本体

どちらの種類も本体長`u32`と、そのバイト列を格納します。
本体の上限は32,768バイトです。
これはコンテナーの上限であり、BASICの空きメモリーに収まることを保証しません。
実行アドレスや固定のロードアドレスは格納しません。
実際の配置と管理情報の更新は、対応ROMの`LOAD`処理へ任せます。

### テキスト

`SAVE ...,A`のソースを、CR（`$0D`）区切りのまま保持します。
ブロックの先頭フラグ、`$1A`終端、ゼロの埋め草、チェックサムは取り除きます。
空プログラムは長さ0です。
各行は1〜65,535の昇順・重複なしの行番号と、空でない本文を持ち、末尾にCRを付けます。
1行はCRを除いて255バイト以下です。
CR以外の`$00`〜`$1F`は受け入れません。
これはホストの入力契約であり、すべての行番号や構文をROMが受理するという意味ではありません。
文字列、カナ、GRAPHを含む高位バイトはUnicodeへ変換しません。

### 内部形式

通常の`SAVE`から復元したJR-HuBASICのプログラム領域を保持します。
各行は「レコード全長`u16`、行番号`u16`、内部コード列、ゼロ1バイト」で構成され、最後に全長0を示すゼロ2バイトを置きます。
各レコードは6バイト以上で、全長と末尾、昇順・重複なしの行番号、プログラム全体の境界を検証します。
空プログラムはゼロ2バイトです。
これは構造検証であり、すべての内部コードや実行時の構文をホストで解釈する検査ではありません。

両形式とも利用者の対応ROMが必要です。
現在は確認済みのJR-HuBASIC 1.0／2.0の完全なROMのSHA-256で適用を限定します。
ROMの版をWAVから推測したり、ホストでBASICの内部コード表を持ったりはしません。
利用方法と制限は[BASICプログラムWAVの利用ガイド](../user/basic-program-wav.md)を参照してください。
